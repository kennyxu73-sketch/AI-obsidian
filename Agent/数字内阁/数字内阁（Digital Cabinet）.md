## 二、 四库物理架构（Vaults Definition）

为了保证数据安全与系统稳定，所有资产按照物理路径严格隔离：

1. **`cabinet/` (用户知识库)**：人类主权区。AI 默认**只读**。存放 Kenny 的原始笔记与项目。
    
2. **`system/` (系统治理库)**：宪法区。存放 `Cursor Rules`、`蓝皮书`、`架构图`。
    
3. **`runtime/` (AI 运行库)**：资产工厂。存放 `Triple-A` 衍生资产（Cards/Audits）及 AI 临时缓存。
    
4. **`tools/` (基础设施库)**：执行区。存放 `Docker`、`Python 脚本`、`本地模型配置`。

## 三、 内阁智能体（Agent Roles）

### 1️⃣ 小忆 (XiaoYi) — 秘书长

- **定位**：唯一对话入口 / 总调度者。
    
- **职责**：理解 Kenny 的模糊意图，拆解任务并分派给其他智能体，汇总最终报告。
    

### 2️⃣ 小画 (Visual Agent) — 可视化专家（新成员）

- **定位**：交互渲染 / 人机界面决策。
    
- **职责**：将复杂的四库逻辑转化为 **Canvas/Kanban**；捕获 Kenny 在画布上的操作并转化为执行指令；负责 `Pending` 状态的可视化标注。
    
- **原则**：不产生内容，只负责“如何让你看明白并好操作”。
    

### 3️⃣ 小黑 (XiaoHei) — 暗箱分析官

- **定位**：Obsidian 守门人 / 结构化引擎。
    
- **职责**：对 4GB 旧笔记进行冷静分析；**只输出 JSON**；决定内容是否值得入库；标注风险点与推断点。
    

### 4️⃣ 小报 (XiaoBao) — 情报官

- **定位**：外部世界连接器。
    
- **职责**：搜索、抓取、RSS 整理；初步判断外部信息的价值等级（A/B/C/D）。
    

### 5️⃣ 小酷 (XiaoKu) — 执行官/技术保障

- **定位**：底层运维 / 脚本执行 / 算力调度。
    
- **职责**：维护 Docker 容器；管理本地 **3090** 推理；执行物理层的文件搬运与备份。
    

### 6️⃣ 小镜 (XiaoJing) — 2C 专家（回忆录/数字人）

- **定位**：情感与叙事负责人。
    
- **职责**：判断内容的记忆价值；适配数字人素材；负责回忆录项目的深度挖掘。
    

### 7️⃣ 小康 (XiaoKang) — 2B 专家（养老平台）

- **定位**：平台化与商业逻辑负责人。
    
- **职责**：将个人知识体系转化为养老 AI 平台的业务逻辑与 Kanban 任务。

## 四、 核心运行流：Triple-A 审计闭环

所有经过内阁处理的知识必须遵循 **Triple-A** 结构并在 Canvas 上可视化：

1. **Note (`cabinet/`)**：Kenny 写作或小报抓取。
    
2. **Card (`runtime/cards/`)**：小黑提取语义，小画在 Canvas 渲染为蓝色节点。
    
3. **Audit (`runtime/audits/`)**：记录血缘，标注 `embedding_access: false`。
    
4. **Review (Canvas)**：小画标记为 `Pending`（黄色）。
    
5. **Finalize**：Kenny 在 Canvas 点击“确认” → 小酷执行回流归档。
    

---

## 五、 交互准则（Kenny's Law）

- **L1/L2 绝不离境**：核心个人隐私必须由小酷在本地 3090 处理。
    
- **可视化即指令**：Canvas 上的连线修改即代表 Pipeline 逻辑调整。
    
- **冲突熔断**：任何 ID 重复或 YAML 损坏，立即生成 `.halt` 并由小画发出红色预警。
