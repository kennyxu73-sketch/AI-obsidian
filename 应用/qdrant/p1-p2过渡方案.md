版本：v1.0  

阶段：Phase 1（Obsidian Embedding 储备）  

目的：建立可用于长期记忆、个性化问答，并为阶段二（Qdrant + Gap Engine）升级预留接口的资料库

  

---

  

## 1. 目录结构建议

00_Cabinet       # 核心知识资产（长期存储）

10_System        # 系统配置、Prompt 模板

20_Runtime       # 日常记录、草稿、生成内容

30_Archives      # 已完成文档与封存内容

说明：

- **00_Cabinet**: 阶段一主要存放“永久参考”资料，结构化良好。  

- **20_Runtime**: 适合阶段一收集的个人回忆、对话、日志记录。  

- **30_Archives**: 用于封存已确认不再修改的资料，为阶段二 Qdrant 提供稳定数据源。

  

---

  

## 2. 元数据模板（YAML）

  

> 每条记录都建议绑定完整元数据，阶段二可直接读取。

  

yaml

id: # 唯一标识，如 Ref_001

created: # 2026-03-19T21:00

source: # 数据来源，如 "用户回忆" / "AI对话" / "文档导入"

type: # "memory" / "preference" / "document" / "conversation"

tags: [] # 主题标签，例如 ["创业", "养老"]

people: [] # 涉及人物，例如 ["Kenny", "父亲"]

location: # 地点信息，可空

emotion: # 情绪标记，如 "喜悦" / "焦虑"

priority: # P0/P1/P2

gap_suspected: false # 潜在逻辑或信息缺口

persona: # 阶段二预留字段

  goals: []

  decision_style: []

  risk_appetite: []

  cognitive_gaps: []

  emotion_pattern: []

embedding_path: # embedding 文件路径或 ID

notes: # 临时备注、待补充内容

16. Embedding 储备策略

  

  

- Embedding 存储路径建议：

  

20_Runtime/embeddings/<id>.npy

  

-   
    
- 绑定元数据：  
    每条 embedding 必须与 YAML 记录关联，便于后续 Qdrant 导入。
- 更新策略：  
    

- 新记录生成 embedding
- 已修改记录更新 embedding
- 删除记录同时清理 embedding

5. 阶段二对接预留

  

|   |   |
|---|---|
|字段/模块|阶段二作用|
|persona|直接用于建立用户画像与认知补全|
|gap_suspected|Gap Engine 自动识别潜在认知缺口|
|embedding|导入 Qdrant 向量数据库，实现高速检索|
|tags/people/location|多维过滤与上下文检索条件|
|priority|查询排序、任务分级参考|
