## 三、 Obsidian Git 关键配置指南

为了实现“无感备份”与“精准确权”，Obsidian 插件必须按照以下规范配置：

### 1. 自动化备份设置 (Automatic)

- **Auto commit interval (minutes)**: 设置为 **30**。每半小时自动在本地生成一个“记忆快照” [cite: 2026-02-11]。
    
- **Auto push interval (minutes)**: 设置为 **30**。确保本地改动能定时同步至 GitHub 云端保险柜。
    
- **Pull on startup**: **开启 (ON)**。每次打开 Obsidian 时，强制对齐云端最新的法典协议，防止逻辑版本冲突 [cite: 2026-02-11, 2026-02-12]。
    

### 2. 审计存证设置 (Commit Message)

- **List filenames affected by commit**: **开启 (ON)**。在每次自动备份的记录中列出改动的文件名，方便 Gem 外审快速定位哪些协议被修改了。
    
- **Commit message**: 默认使用 `vault backup: {{date}}`。这为未来的“回滚”提供了清晰的时间轴线 [cite: 2026-02-11]。
    

### 3. 同步策略 (Sync)

- **Push on commit-and-sync**: **开启 (ON)**。确保手动点击状态栏同步时，一步到位完成云端确权。
    
- **Merge strategy**: 设置为 **Merge**。当多端修改同一份计划时，系统会尝试自动合并改动 [cite: 2026-02-10]。

## 四、 系统使用方法与审计流

### 1. 日常确权流程

- **自动模式**：在 `000_Cabinet_System`（法典库）中修改内容后，无需干预，系统会在 30 分钟内自动同步 [cite: 2026-02-11]。
    
- **手动模式**：完成重大计划（如小康养老平台新逻辑）后，点击 Obsidian 状态栏图标，立即完成“云端盖章” [cite: 2026-02-12, 2026-02-19]。
    

### 2. Gem 影子审计 (核心能力)

1. **提交 Diff**：通过 `git diff` 提取代码或协议的改动。
    
2. **对照法典**：将改动贴给 Gem，它会调取 `cabinet-system` 分支中的规范进行比对 [cite: 2026-02-12]。
    
3. **合规判定**：Gem 给出 [通过/风险/拒绝] 的审计意见，确保 AI 的自我迭代不违背 Kenny 的原始设计 [cite: 2026-02-10, 2026-02-19]。

## 五、 安全与脱敏规范 (Security)

- **SSH 链路**：全线放弃密码登录，采用 Mac 钥匙串管理的 SSH 秘钥，确保自动化过程无需人工输入 [cite: 2026-02-11]。
    
- **零密钥原则**：任何 `.md` 文档严禁出现 `github_pat_` 或 `Client_Secret`。所有敏感密钥应存储在本地环境变量或专属加密文件中，严禁上传 GitHub [cite: 2026-02-11]。
