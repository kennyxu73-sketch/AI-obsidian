## 二、 跨平台分身部署 (Deployment)

### 1. Dify 端 (逻辑大脑)

- **部署方式**：每个 Agent 独立为一个 Dify Chat App。
- **身份清洗**：在 System Prompt 顶端加入“霸权条款”，强行覆盖 3090 底层“忆镜师”设定。
- **工具挂载**：仅“小报”挂载搜索与视频解析工具，“小憶”挂载 Obsidian 写入 Skill。

### 2. Obsidian 端 (物理官邸)

- **Smart Connections**：全员“通用官邸”，负责全库语义检索与知识唤醒。
- **Copilot**：专家对话区，用于“小镜”和“小康”进行深度专题讨论。
- **Templater/Dataview**：由“小酷”维护，负责知识卡片的自动化排版与看板生成。
    
### 3. iPhone 端 (随身入口)(仅一轮对话)
- **快捷指令**：通过 API 直接调用 Dify。
- **主要功能**：闪念捕捉（小憶）、紧急搜索（小报）。

## 三、 知识流转与审核机制 (Workflow)

| **Agent** | **核心 SOP 模式** | **判定维度**             | **最终动作**                        |
| --------- | ------------- | -------------------- | ------------------------------- |
| **小报**    | **准入审核制**     | **价值分级 (A/B/C/D)**   | 只有 A/B 级才建议入库，C 级存摘要，D 级丢弃。     |
| **小憶**    | **四象限调度制**    | **时间/意图优先级 (P0-P3)** | 优先处理当前对话，闲时整理笔记，定时发起复盘。         |
| **小酷**    | **稳定性保障制**    | **技术风险/自动化效率**       | 确保 3090 不崩，确保 Skills 运行，确保目录不乱。 |
| **专家组**   | **项目交付制**     | **内容深度/逻辑性**         | 产出高质量的 [憶镜] 或 [慰康] 专题 Markdown。 |

### 1. 采集流程 (小报执行)
- **小报** 每日自动搜集“养老 AI”、“2C 记忆产品” , AI进展等核心领域动态。
- 
- 生成 Markdown 格式的**知识卡片**，初始标签设定为 `#待审核`。
#### a. 缓冲区 (Pending Review)
- 所有新内容存入 `100_Inbox_Intelligence/00_Pending_Review`。
- **严禁** Agent 直接将未经审核的内容写入正式项目目录。
#### b. 统帅审核定级 (HITL)

统帅每日对缓冲区内容进行评级：
- **级别 A (战略级)**：存入核心知识库，触发 3090 深度解析。
- **级别 B (参考级)**：存入具体项目文件夹 (小镜/小康领地)。
- **级别 C (碎片级)**：保留摘要卡片，删除长文。
- **级别 D (废弃)**：直接销毁。
