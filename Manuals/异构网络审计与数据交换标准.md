# 异构网络审计与数据交换标准 (v1.2)

## 1. 核心定义：多维网络节点 (Network Nodes)

在 AI-Obsidian 系统中，数据跨越了三个互不信任的网络平面。**n8n** 必须在这些平面之间建立“安全受控的跳板”。

- **L1：私有算力层 (3090 Cluster)**：处于物理内网，运行 Dify、Ollama。通过 Docker 内部网络通信。
    
- **L2：虚拟骨干层 (ZeroTier V-LAN)**：连接你的手机、笔记本与 3090。即使你在外网，也通过 ZeroTier 的静态 IP（如 `10.147.17.x`）访问内网资源。
    
- **L3：公共代理层 (External API/Proxy)**：连接企微、GitHub。通过代理（如 7890 端口）出海，通过 Webhook 回流。
    

---

## 2. n8n 的异构路由职责 (n8n Routing Roles)

### 2.1 穿透与鉴权 (Tunneling & Auth)

- **ZeroTier 接入审计**：n8n 必须识别请求是来自本地回环（`127.0.0.1`）还是虚拟内网（`10.147.17.x`）。
    
- **路由策略**：
    
    - **Internal Only**：敏感审计数据（如 Dify 的原始法典）仅在 L1 物理层流转。
        
    - **ZeroTier Access**：审计报告（Markdown）允许推送到 ZeroTier 覆盖的设备（如你的 iPad/手机）。
        

### 2.2 跨境路由 (Border Routing)

- **出站（To Ext）**：n8n 将 Dify 的审计结论通过 3090 的宿主机代理推送到企微。
    
- **入站（From Ext）**：企微的审批回调先到达公网网关（如 Cloudflare/FRP），转发至 n8n，n8n 再通过内部网段推送到 Dify 执行确权。

## 3. 混合网络下的接口规划 (Interface Mapping)

|**场景**|**协议**|**源地址 (Source)**|**目标地址 (Target)**|**审计拦截点**|
|---|---|---|---|---|
|**代码提交**|Git Hook|Cursor (Local)|n8n (127.0.0.1)|**Pre-commit 静态扫描**|
|**远程审批**|HTTPS|企微 (Public)|n8n (Public IP/FRP)|**WeCom Token 签名校验**|

|**异地查看**|ZeroTier|手机 (10.x.x.x)|n8n (10.x.x.x)|**ZeroTier 设备 ID 验证**|

## 4. 特别审计环节：网络环境校验 (Context-Aware Audit)

为了初设期的“特别小心”，n8n 需在审计流中增加 **`Environment_Check`** 节点：

1. **物理安全校验**：如果审计指令来自非 ZeroTier IP，且试图修改核心代码，**一键熔断**并锁定 Dify 账户。
    
2. **DNS 分流审计**：n8n 需判断当前 API 请求是否需要走 VPN 代理（如调用 Gemini），还是走本地局域网（如调用 3090 上的 Ollama），防止数据绕路导致的信息泄露。
    
3. **大流量拦截**：检测 ZeroTier 网络波动，若网络质量差，n8n 自动将 Dify 的“深度报告”压缩为“精简摘要”，优先保障核心指令送达。
    

---

## 5. 初始配置保护 (Setup Hardening)

- **Zerotier 节点隔离**：在 n8n 所在机器配置 `iptables`，仅允许指定的 ZeroTier 成员访问 `5678` 端口。
    
- **证书管理**：n8n 与 Dify 之间的所有 `HTTP Request` 必须带上特定的 `Cabinet-Secret-Header`，防止内网其他容器模拟指令。
