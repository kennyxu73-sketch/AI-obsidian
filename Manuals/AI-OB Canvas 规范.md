# AI-OB Canvas 治理规约 (v1.2)

**版本：** 1.2 (Final)

**状态：** 系统治理核心规范

**适用范围：** AI-OB 系统中所有 Canvas、架构图、流程沙盘

---

## 一、 系统定位：结构可视化层 (Visual Mapping)

Canvas 在 AI-OB 中属于**结构可视化层**。其核心定位是：**文档为真，Canvas 为影**。

- **核心作用**：
    
    - 提供系统的“上帝视角”，帮助统帅快速理解复杂逻辑。
        
    - 作为架构孵化器，支持在 Canvas 上进行直观的设计与重构。
        
- **SSOT 准则**：Canvas 本身不存储事实，事实始终锚定在 Obsidian 文档（Markdown）中。
    
- **存在哲学**：文档是逻辑骨架（真），Canvas 是感知表象（影）。
    

---

## 二、 空间治理：三维分区协议 (The Grouping Protocol)

这是 v1.2 版本的核心升级。为防止视觉熵增，Canvas 必须使用 `group` 节点执行 **“分区而治”**：

1. **文件存储区 (Top Zone)**:
    
    - **位置**：Canvas 顶部。
        
    - **容纳**：`SSOT 核心`、`系统定位` 等 L1 资产节点。
        
    - **意义**：代表系统的“静止质量”与事实来源。
        
2. **治理闸门区 (Left Zone)**:
    
    - **位置**：Canvas 左侧。
        
    - **容纳**：`设计规范`、`使用原则`、`人工审计` 等金色节点。
        
    - **意义**：代表规则的输入，人工对自动化的约束。
        
3. **系统处理区 (Center/Right Zone)**:
    
    - **位置**：中心及右侧广大区域。
        
    - **容纳**：`处理引擎`、`自动化 Agent`、`存储归档`。
        
    - **意义**：代表系统的“动态能量”与执行过程。
        

---

## 三、 设计规范 (小画职能)

### 1. 节点聚合原则 (Anti-Flattening)

- **原子化聚合**：严禁平铺细碎的操作步骤。一个节点必须是一个**“功能完备的子系统”**或**“权力中心”**。
    
- **棋子化指标**：单个 Canvas 的核心功能节点数量应控制在 **7±2 个**。
    
- **信息内聚**：
    
    - **标题**：`[图标] 标题`。
        
    - **角色**：定义节点身份（如：治理节点、执行节点、归档节点）。
        
    - **职能**：用 `→` 描述内部逻辑流向。
        
    - **状态**：使用信号灯 `🟢/🟠/🔴` 标注运行状况。
        

### 2. 颜色语义规范

|**颜色代码**|**含义**|**典型示例**|
|---|---|---|
|**#8A2BE2 (紫)**|**L1 核心资产 / SSOT**|Obsidian 文档, 索引库|
|**#1E90FF (蓝)**|**L2 自动化处理**|处理引擎, 自动化分身|
|**#FFD700 (金)**|**人工介入 / 治理规约**|设计规范, 审计闸门|
|**#32CD32 (绿)**|**外部输入 / 原始捕捉**|WeChat 采集, 语音入口|
|**#FF4500 (红)**|**异常 / 风险告警**|熔断提示, 冲突阻断|

### 3. 连接线动力学

- **实线 (`solid`)**：代表人工参与、规则介入或物理位移。
    
- **虚线 (`dashed`)**：代表纯自动化数据流。
    
- **跨区回流**：视觉上必须存在一条从【处理区】连回【存储区】的反向虚线，标注为 **“🔄 真值回流”**。
    

---

## 四、 形成机制：螺旋上升的闭环 (The Formation Loop)

系统遵循 **“文-图-文”** 的螺旋上升逻辑：

1. **逻辑定义**：Markdown 定义基础协议。
    
2. **自动映射**：小画依据文档生成分区明确的 Canvas。
    
3. **视觉重构**：统帅在 Canvas 上通过拖拽和重组进行**“人工微调”**。
    
4. **真值同步**：小黑解析 Canvas 变动，并将优化后的拓扑结构回写至 Markdown 协议，完成 SSOT 更新。
    

---

## 五、 存储、Embedding 与自动化

1. **存储建议**：Canvas 建议单独管理，但必须与对应文档“影随真身”（同目录归档），便于 Agent 快速定位关联。
    
2. **Embedding 策略**：
    
    - Canvas 原始 JSON 不进入 Embedding。
        
    - **策略**：小画提取 Canvas 节点的“职能描述”并以列表形式存入文档 YAML 区，从而间接参与向量搜索。
        
3. **生命周期**：
    
    - **设计态**：Canvas 作为草案孵化架构。
        
    - **运行态**：作为监控面板展示 🟢/🟠/🔴 状态。
        
    - **归档态**：随系统变更进入 `/archive` 历史库。
        

---

## 六、 未来自动化：Canvas Agent (小黑 & 小画)

1. **小画 (Visual Agent)**：执行“空间治理协议”，负责将文档原子化合并，并输出带 Group 分区的 JSON。
    
2. **小黑 (Logic Agent)**：执行“真值回流协议”，负责检测 Canvas 连线变动，自动同步修改对应的 SSOT 文档逻辑。
    

---

**总结：AI-OB v1.2 规范下，Canvas 不再是静态的说明图，而是具备物理分区、高度聚合、且能反向驱动真值的“架构操控台”。**
