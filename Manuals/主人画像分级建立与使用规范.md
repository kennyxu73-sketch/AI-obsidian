## 3. Tier 定义

### Tier A（公理层）

- **内容**：战略公理、数据主权、本地优先等 **可检验命题**（以 `Kenny_Cognitive_Profile.md` 为主）。
- **使用**：**L2** Pre-Gap、偏差预警、封印前对照；可通过工作流变量 `kenny_profile_excerpt` 或 HTTP **`p_tier_a_main`**（仅建议 L2 配置）。
- **禁止**：**L1** 不得仅凭 Tier A 做「最终公理判决」或编造未出现的承诺；L1 默认 **不** 拉取 Tier A 全文。

### Tier B（L1 注入层）

- **内容**：短上下文：当前常用项目名、称呼约定、活跃目标摘要等（`Kenny_Profile_L1_Context.md`）。
- **使用**：**L1** 脱水小结时 **锚定指代、消歧**；HTTP slug **`p_tier_b_l1_ctx`**。
- **禁止**：Tier B **不可替代** Tier A 做冲突裁决；不得将 Tier B 当作「已批准公理全集」。

### Tier C（可选 RAG / 知识库层）

- **内容**：经裁剪、可检索的切片（可放在 `Dify/_kb_sources/...` 等受控树）。
- **使用**：Dify Knowledge / P2 Qdrant；须遵守 [Dify_应用开发规范](Dify_%E5%BA%94%E7%94%A8%E5%BC%80%E5%8F%91%E8%A7%84%E8%8C%83.md) §6、`sync_to_dify.py` 过滤规则与 `embedding_access`。
- **禁止**：全量 RAW、`.audit.yaml`、未脱敏敏感段落进入生产检索库。

## 4. 建立与变更

- 与炼化规划一致：**严禁跳级**（RAW 不得直炼为画像）；**画像分流**——写入 `Kenny画像/` 须经 Kenny Gate / 方案 B。
- Tier A/B 正文变更建议带 **ref_id** 或 CHANGELOG 可追溯（与内阁审计习惯一致）。
- **Tier B**（`Kenny_Profile_L1_Context.md`）可由统帅高频小改；**Tier A** 变更应更审慎。

| 场景 | 允许 Tier | 推荐方式 | 禁止 |

## 6. 技术落地：`prompt_http_bridge.py`（认知隔离）

**物理路径（硬编码）**：`SSOT_ROOT/Agent/小忆/Kenny画像/` 为 **受保护目录**。

1. **Slug 命名契约**：凡映射到该目录下 **`.md`** 的条目，slug **必须** 以 **`p_tier_`** 开头。  
   - `p_tier_b_l1_ctx` → `Agent/小忆/Kenny画像/Kenny_Profile_L1_Context.md`  
   - `p_tier_a_main` → `Agent/小忆/Kenny画像/Kenny_Cognitive_Profile.md`  

2. **显式放行列表**：仅 **上述路径**（及 TOOLS 内与同表同步的 frozenset）可通过 HTTP 读取；**禁止**通过遍历或模糊 slug 访问目录内其他文件（如 `Kenny 认知画像报告.md`）除非未来 **单独登记** 新 slug 与 Tier。

3. **侧车拒绝**：路径或文件名命中 `.audit.yaml`、`card.yaml` 等规则 **一律拒绝**（即使误配 allowlist）。

4. **非画像类 Prompt**（如 `xiaoyi_l1_inbox_summary`）**不** 使用 `p_tier_` 前缀，以免破坏既有 Dify 节点。

**示例**（需 `CABINET_PROMPT_TOKEN`）：

```bash
curl -s -H "Authorization: Bearer $CABINET_PROMPT_TOKEN" \
  "http://127.0.0.1:8765/prompts/p_tier_b_l1_ctx" | head
```

## 8. 验收（运维自检）

- L1 工作流配置的 HTTP slug 仅为 **`p_tier_b_l1_ctx`**（或等效短变量），**非** `p_tier_a_main`。
- 对未登记画像文件请求 `GET /prompts/...` 返回 **404**。
- 任意 Agent 文档引用画像时 **链接本文 Tier 表** 或炼化规划，避免口头约定漂移。
