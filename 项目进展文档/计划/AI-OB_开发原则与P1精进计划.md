# AI-OB 开发原则与 P1 精进计划

> **与主锚关系**：阶段步骤、闸门、Gantt 以 [[AI-OB 路线图规划（P0 - P2）]] 为准。  
> **与并行笔记关系**：[[AI Obsidian · P0-P2整体演进路线图]] 与主锚表格高度重叠，仅作摘要或历史对照；**执行与验收以主锚文档为 SSOT**，避免双份维护导致不一致。

## 总策略（1.0 导向）

- **先 1.0 上线，再精进**：除下文「不可动摇」项外，以「能稳定跑、可回滚、可验收」为阶段完成标准。
- **效率优先，规范不丢**：规范收缩为少而硬的底线；其余用短 DoD、轻复盘代替重流程。

---

## 一、开发原则

### 1. 不可动摇（底层）

| 原则 | 要求 |
|------|------|
| **数据安全** | 批量写库 / 改 YAML：禁止静默覆盖同名；关键批跑前可回退（git / 备份）；失败可停、可定位。 |
| **SSOT 与结构** | 改目录、迁库、上云、单一事实源由 **人拍板**；AI 只给方案与风险。 |
| **选型顺序** | P0 插件与现成能力 → P1 Skill → P2 编排（Dify / n8n）→ CLI → 最后才深度自研（与 [[技术解决方案逻辑手册|内阁技术解决方案逻辑手册]] 一致）。 |
| **规模调试** | 全量（如 4G）前，必须在**小样本（如 10 篇黄金案例）**上跑通。 |

### 2. AI 与人协作（Cursor / Agent）

- **口令**：先分类，后评估；先验证，后放量；先可逆，后自动。（详见 [[cursor 开发人机协作原则]]）
- **每个里程碑**：唯一主目标 + 3～5 条 **DoD（完成定义）** + 明确 **不做清单**。
- **变更预算**：搭建期 `.cursorrules` / 规则级大改每周 ≤ 1～2 次；大改后留短观察期再叠改。
- **证据优先**：争议以日志、样本输出、指标为准。

### 3. P1 技术边界（对齐主锚）

- **长期记忆 1.0**：**Notes / System 两域** + **Summary → Chunk** + 可解释检索；**复杂向量库、Code 域 RAG、Rerank** 归入 **P2**（见主锚 P1 S3、P2 S2）。
- **老笔记**：分批、分级（A/B 优先）、冲突进隔离桶；**不全量硬灌**（主锚 P1 S1）。

## 二、P1 精进计划（切片与里程碑）

### 1. 企微 Bot — P1 MVP（三条）

1. **推送**：审批结果、积压提醒、日/周关键节点（单向可靠即可）。
2. **收录**：一条主入口（转发或关键词 → **Inbox / 待处理队列**）；**默认不直写 SSOT**。
3. **只读查询**：今日任务摘要、本周主题等（**读库或读索引，默认不写库**）。

超出三条的多轮编排、复杂 Agent 归入 **P1.1 / P2**。

### 2. 主锚 P1 S1–S5 → 里程碑映射（允许并行）

下列顺序为**依赖建议**；**S5（周闭环）与 S3（检索雏形）在人力允许时可与前排期部分并行**，不必等 Gantt 上一条完全结束再启动（以主锚文后「P1 甘特说明」为准）。

| 顺序 | 主锚步骤 | 切片要点 | 最小可观测结果（示例） |
|------|----------|----------|------------------------|
| ① | **P1 S1** | 小批量导入管线、冲突 / 隔离桶、每批极简报告 | 10～50 篇批次可重复成功；冲突不污染主库 |
| ② | **P1 S3** | 两域划分、Summary/Chunk 规则、可解释检索 | 周决策类问题能引用到具体笔记路径或标题 |
| ③ | **P1 S5** | 周计划 / 日执行 / 周复盘模板与固定位置 | 一周走完一圈并留下一篇「结论资产」 |
| ④ | **P1 S2 + 企微** | 流程产品化薄实现 + 企微三条 MVP | 企微与 Obsidian/Runtime 间有一条稳定、可日志追踪的链路 |
| ⑤ | **P1 S2** | 审批超时降级、恢复闭环、积压提醒 | 超时无违规写入 SSOT |
| ⑥ | **P1 S4** | 进度/冲突/健康度 1～2 个指标；周报半自动或模板化 | 周复盘能贴客观数字 |

### 3. 与阶段闸门的对应（主锚 P1 → P2）

主锚要求：分批导入稳定、审批积压可控、检索质量达标、周运营闭环稳定。

| 闸门条件 | P1 精进中的「最小版」验收 |
|----------|---------------------------|
| 分批导入稳定 | 每批有报告；冲突可追溯；成功率趋势可观察 |
| 审批积压可控 | 超时策略生效；**企微通道不得绕过 SSOT 审批** |
| 检索质量达标 | 回答可解释（路径/标题级引用）；误召回主观评估下降 |
| 周运营闭环稳定 | 每周至少一篇可复用结论；建议周目标达成率 ≥ 70%（主锚建议值） |

## 三、周节奏落地（对齐主锚）

主锚「每周固定节奏」建议：

- **周一**：周目标与里程碑对齐  
- **周中**：功能开发 + 审批处理 + 风险清单更新  
- **周六**：信息分级与去噪（A/B/C/D）  
- **周日**：周复盘（指标、偏差、下周策略）  

**补充**：周日复盘须对照**本周里程碑 DoD**，未达标则进入下周 `Now` 唯一关键动作，避免与 `Next` 候选混跑。
