# 多源对话收件法典 (Multi-Source Dialogue Ingest Protocol)

**版本**：v2.1 **生效日期**：2026-03-29 **状态**：#Approved / #Infrastructure **Ref_ID**：`P0-DIALOG-INBOX-20260329`

## 一、 核心愿景

为 AI-OB 建立统一的、具备主权意识的“外部感应口岸”。所有源自 Dify、Cursor、OpenClaw 等 Agent 的原始对话，必须在进入内阁前进行“物理对齐”与“安全性脱敏”，确保长期记忆的纯净度与可追溯性。

---

## 二、 三大底层法条 (The Iron Laws)

### 1. 增量追加协议 (Incremental Protocol)

- **规则**：**严禁默认覆盖现有文件**。以 `source` + `session_id` 为全局唯一键。
    
- **执行**：当新的对话块入库时，若目标会话文件已存在，系统必须仅在文件末尾追加新内容，并强制更新索引（Manifest）中的 `last_captured_at` 戳记。
    
- **目的**：确保长周期对话的连续性，防止因同步冲突导致的历史记忆丢失。
    

### 2. 故障隔离红线 (Fault Isolation)

- **规则**：**单点崩溃，全局继续**。
    
- **执行**：同步脚本（`run_sync_all`）必须对每个适配器（Adapter）实施独立异常处理。
    
- **记录**：任何单源采集失败，必须仅将错误摘要写入 `RUNTIME_ROOT/ai_dialogue_inbox/sync_errors.log`，严禁中断其他正常源的采集。
    
- **目的**：保证在跨平台（如 Windows 端断连）复杂环境下的系统自愈能力。
    

### 3. 严格格式校验 (Strict Validation)

- **规则**：角色块必须采用“机读注释锚点”结构。
    
- **标准格式**：
    
    Markdown
    
    ```
    ## User (或 Assistant)
    [正文内容]
    ```
    
- **目的**：在不破坏 Markdown 人类阅读美感的前提下，为后续的 **Gap Engine** 和 **Refinery (炼化器)** 提供无歧义的语义切片锚点。

## 三、 数据流与存储规范

### 1. 存储路径

- **收件箱 (Inbox)**：`RUNTIME_ROOT/ai_dialogue_inbox/`
    
- **索引清单 (Manifest)**：`inbox_manifest.jsonl`（包含 `session_id`, `source`, `file_path`, `last_captured_at`）。
    

### 2. 写入主权 (PSR)

- 任何针对 `/200_Operations/` 及以上层级的自动写入，必须调用 `cabinet_sentinel.py` 进行物理主权校验。在 `AIOB_PSR_DISABLED=1` 模式下仅限本地测试使用。

## 四、 晋升路径 (Promotion Path)

与 TOOLS `dialog_inbox.py` / `enseal_skill.py` 一致，分 **两条**（可并行存在）：

1. **RAW 层**：原始对话存放于 `RUNTIME_ROOT/ai_dialogue_inbox/`（`inbox_manifest.jsonl` 索引）。

2. **DRAFT 层（语义储备，默认）**：`enseal_skill --materialize-from-inbox <合规.md> --seal-target-dir <相对SSOT根子路径>` 生成 **`RUNTIME_ROOT/drafts/<batch>/` 下 Triple-A**；或经 3090 Dify + Ollama 炼化后由统帅粘贴/写入草案。**不是**自动把全文灌入 `Cognitive_Patch_Draft.md`。

3. **DRAFT 层（可选 · 认知 Patch 结构化）**：在 `RUNTIME_ROOT/Cognitive_Patch_Draft.md` 中维护含 `Target_SSOT_Path:` 的 `##` 块 → `enseal_skill --materialize-from-cognitive-patch` → 同上 Triple-A 草稿目录。

4. **TRUTH 层 (SSOT)**：草稿批经 `.seal_ready` 或 `review_status` 批准后 `enseal_skill --seal-batch` 封印至 `000_Cabinet_System/`；**须 Kenny 闸门**。
