# 多源对话收件法典

> **同源**：[`Internal_Cabinet_Tools/dialog_inbox.py`](file:///Volumes/Cabinet/cabinet/Cursor_Workspace/Internal_Cabinet_Tools/dialog_inbox.py) 模块顶部文档字符串与本文件一致；修订须双处同步。

## 落盘

- 会话正文：`RUNTIME_ROOT/ai_dialogue_inbox/*.md`
- 索引：`RUNTIME_ROOT/ai_dialogue_inbox/inbox_manifest.jsonl`（每会话一行 JSON）
- 适配器故障日志：`RUNTIME_ROOT/ai_dialogue_inbox/sync_errors.log`

## 1. 增量追加协议（Incremental Protocol）

- **规则**：严禁默认覆盖。以 **`source` + `session_id`** 为全局唯一键。
- **动作**：`append_turn` 时，若目标会话文件已存在，**仅在文件末尾**追加新的 `## User` / `## Assistant` 块（含法定 `<!-- captured_at: ... -->`），并 **强制** upsert `inbox_manifest.jsonl` 的 **`last_captured_at`**。
- **意义**：长对话多次同步保持完整时间线，避免整文件重复拷贝。

## 2. 故障隔离红线（Fault Isolation）

- **规则**：单点崩溃，全局继续。
- **动作**：`run_sync_all()` 对每个 Adapter **单独** `try` / `except`；禁止一路失败拖垮全局。
- **记录**：失败 **必须** 追加写入 **`sync_errors.log`**（含时间、`adapter_id`、异常摘要）。
- **意义**：例如某一源 API 断连时，其他源仍可入库。

## 3. 严格格式校验（Strict Validation）

- **规则**：唯一合法结构为二级标题（**仅** `## User` 或 `## Assistant`），**换行后紧跟一行**：

  `<!-- captured_at: <ISO8601>Z -->`

  再换行为正文，直至下一角色标题。

- **意义**：机读注释不破坏 Markdown 人读；为 Dify / Python chunking 与块解析提供时间锚点。

## manifest 必填字段

每行 JSON 须含：`session_id`、`source`、`file_path`（相对 `RUNTIME_ROOT` 的 POSIX 路径）、`last_captured_at`。

## 低信任区入站

`import_file` 从中转目录等读取源文件，**校验并规范化后写入** `ai_dialogue_inbox/`，不原地信任源路径。

## 与 enseal 衔接

`enseal_skill --materialize-from-inbox` 从合规 inbox `.md` 提取角色块生成 Triple-A 草稿；封印与变更 SSOT 仍须 Kenny 审批流程。
